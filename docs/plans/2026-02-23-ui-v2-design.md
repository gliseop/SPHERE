# MAGISTRY Web UI v2 — Проектный документ

Дата: 2026-02-23

## Контекст и цель

Первая версия интерфейса заложила базу: D3-граф, HUD-стиль, воспроизведение прогонов. Вторая версия устраняет ключевые проблемы: отсутствие контекста (непонятно, что происходит), минимальный объём информации на экране и ограниченность инструментов управления симуляцией. Цель — сделать из мониторинговой страницы полноценный рабочий инструмент исследователя.

## Архитектура приложения

Приложение делится на два раздела с переключением в заголовке: «Монитор» и «Сценарии». Переключение реализуется через состояние React без маршрутизатора — объём приложения не требует отдельных URL.

## Раздел «Монитор»

### Компоновка

Три колонки фиксированной ширины вокруг гибкого центра:

- **Левая (220 пкс):** верхняя часть — управление прогонами (RunSelector), нижняя — постоянно видимый список агентов (AgentList).
- **Центр (flex):** граф агентов (SimGraph).
- **Правая (300 пкс):** лента активности (ActivityFeed) — объединяет мировой нарратив, сообщения и саморефлексию.
- **Нижняя полоса (90 пкс):** сжатая лента событий (EventTimeline).

### Список агентов (AgentList)

Всегда виден без каких-либо кликов. Каждая строка: цветной маркер роли, имя агента (из данных симуляции), бейдж роли, горизонтальная полоса репутации с числовым значением. При воспроизведении строка кратко подсвечивается, когда агент становится участником события. Клик по строке — выбор агента (синхронизируется с графом и фильтрует ленту активности).

### Лента активности (ActivityFeed)

Заменяет текущую правую панель AgentPanel. Показывает три типа записей, сгруппированных по раундам:

**Мировой нарратив** — текстовое описание раунда из поля `world_event.payload.narrative`. Отображается в начале каждой группы раунда, выделен фоном. Иконка 🌍.

**Сообщение** — отправитель → получатель, текст сообщения, бейдж «ПРИВ» для приватных. Стрелка меняет цвет: красная для подозрительных связей, фиолетовая для приватных, серая для публичных.

**Саморефлексия** — записи типа `self_reflection` с полем `content`. Курсивный стиль, иконка 💭. Агент-аудитор генерирует преимущественно этот тип записей — наблюдения за миром без прямого взаимодействия.

Лента автоматически прокручивается во время воспроизведения. При выборе агента фильтрует записи, где он участвует.

### Расширения формата данных

Два дополнения к формату JSONL без нарушения обратной совместимости:

`world_event.payload.narrative` (строка, необязательное) — текстовое описание ситуации в начале раунда.

Новый тип события `self_reflection`:
```json
{
  "round": 3,
  "event_type": "self_reflection",
  "agent_id": "aud_inspector",
  "payload": { "content": "Наблюдаю учащение контактов мэра с подрядчиками..." },
  "timestamp": "..."
}
```

### Имена агентов

Имена берутся из сопроводительного файла `<run_name>_names.json` в директории `results/`. Формат: объект `{"agent_id": "Отображаемое имя"}`. Бэкенд включает имена в `meta`-сообщение WebSocket. Фронтенд хранит маппинг в состоянии и применяет его везде: на узлах графа, в списке агентов, в ленте активности. При отсутствии файла — отображается исходный ID.

### Тёмная тема

CSS-переменные с двумя наборами значений под `[data-theme="light"]` и `[data-theme="dark"]`. Переключатель в правой части заголовка (иконка луны/солнца), состояние сохраняется в `localStorage`. По умолчанию — светлая тема.

## Раздел «Сценарии»

### Список сценариев

Карточки с: названием, количеством агентов, количеством раундов, датой последнего запуска. Кнопки действий: «Запустить» (▶), «Редактировать» (✎), «Удалить» (✗). Кнопка «Создать сценарий» в заголовке раздела открывает редактор.

### Редактор сценариев

Форма с разделами:

- **Основное:** название (строка), описание (текстовое поле), количество раундов (число), seed (число или «случайный»).
- **Агенты:** список редактируемых строк. Каждый агент: имя (строка), ID (авто из имени), роль (выпадающий список: Чиновник / Подрядчик / Аудитор), начальная репутация (ползунок 0–10). Кнопки добавить/удалить строку.
- **Параметры мира:** текстовое поле для дополнительных параметров в формате JSON.
- **JSON-превью:** сворачиваемый блок с итоговой конфигурацией сценария.

Кнопки формы: «Сохранить» и «Запустить» (сохраняет и немедленно запускает симуляцию, после чего переключает вид на «Монитор» с активным прогоном).

### API бэкенда (новые эндпоинты)

```
GET    /api/scenarios              — список сценариев
POST   /api/scenarios              — создать
GET    /api/scenarios/{id}         — получить
PUT    /api/scenarios/{id}         — обновить
DELETE /api/scenarios/{id}         — удалить
POST   /api/scenarios/{id}/run     — запустить прогон
```

Сценарии хранятся в директории `scenarios/` как JSON-файлы. Запуск вызывает симуляцию и стримит результат через существующий WebSocket-механизм.

## Тёмная тема — цветовая схема

| Переменная       | Светлая     | Тёмная      |
|-----------------|-------------|-------------|
| `--bg`           | `#ffffff`   | `#0f0f0f`   |
| `--surface-1`    | `#ffffff`   | `#1a1a1a`   |
| `--surface-2`    | `#f5f5f5`   | `#242424`   |
| `--border`       | `#eaeaea`   | `#2e2e2e`   |
| `--text-primary` | `#111111`   | `#e8e8e8`   |
| `--text-muted`   | `#666666`   | `#888888`   |
| `--accent`       | `#f97316`   | `#f97316`   |

Акцентный оранжевый остаётся одинаковым в обеих темах.

## Разбивка на задачи реализации

1. Тёмная тема: CSS-переменные + переключатель в заголовке
2. Расширение бэкенда: имена агентов из `_names.json`, новые event_type в `WsMessage`
3. AgentList: новый компонент в левой колонке
4. ActivityFeed: новый компонент, заменяет AgentPanel в правой колонке
5. Обновление SimGraph: подписи узлов из имён, анимация активных рёбер
6. Раздел «Сценарии»: навигация + список + редактор + API-интеграция
7. Обновление тестовых данных: добавить `_names.json` и примеры `self_reflection`, нарратив в `world_event`
8. Интеграционное тестирование через Playwright
