# Гибридный поиск и библиотека синтетических интервью

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Цель:** заменить mock-эмбеддинги на локальную мультиязычную модель, добавить BM25 в поиск по памяти агентов и построить библиотеку нарративных интервью для обогащения личностей агентов.

**Обоснование:** текущая реализация использует SHA256-хеши вместо семантических эмбеддингов, что обнуляет смысл извлечения по релевантности в потоке памяти. Параметрические описания личностей (HEXACO/Dark Triad как числа) значительно уступают нарративным описаниям на основе интервью (Park et al. 2024 показывают разницу 0.74 vs 0.85 на GSS-опроснике).

## Секция 1. Гибридный поиск по памяти агента

### 1.1. Локальные эмбеддинги

Новый класс `LocalEmbeddingProvider` в `llm.py`, реализующий протокол `EmbeddingProvider`. Модель: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (мультиязычная, 384 dim, ~120 МБ). Загрузка ленивая (при первом вызове `embed()`). Выбор обусловлен тем, что симуляция ведётся на русском языке, а англоязычные модели (all-MiniLM-L6-v2) показывают низкое качество на кириллических текстах.

### 1.2. BM25 в MemoryStream

Добавить `rank-bm25` (`BM25Okapi`) как второй индекс внутри `MemoryStream`. При каждом вызове `add()` токенизированный текст записи добавляется в корпус, индекс пересоздаётся (корпус мал, порядка сотен записей на агента, пересоздание BM25Okapi занимает микросекунды). При `retrieve()` формируется два набора скоров: косинусное сходство по эмбеддингам и BM25 по токенам.

Токенизация: простое разделение по пробелам с приведением к нижнему регистру. Стемминг и удаление стоп-слов не требуются, так как корпус мал и терминология специфична.

### 1.3. Гибридная формула

Расширение формулы Park et al. (2023):

```
score = alpha * recency + beta * cosine_relevance + gamma * bm25_relevance + delta * importance
```

Где:
- `recency = 0.995 ^ rounds_ago` (без изменений)
- `cosine_relevance` = косинусное сходство запроса и записи (от -1 до 1, нормализованное к [0,1])
- `bm25_relevance` = BM25 скор, нормализованный к [0,1] через min-max по текущей выборке
- `importance` = оценка важности записи, нормализованная к [0,1] (importance / 10.0)

Коэффициенты по умолчанию: `alpha=0.5, beta=2.0, gamma=1.5, delta=2.0`. BM25 получает меньший вес, чем семантика, поскольку в нашем контексте много повторяющихся терминов (закупка, дело, предложение), и лексическое совпадение менее информативно, чем смысловая близость.

### 1.4. Зависимости

- `rank-bm25` (~5 КБ, только numpy)
- `sentence-transformers` (тянет torch, ~800 МБ при первой установке)

Добавляются как опциональная группа `[search]` в pyproject.toml. При отсутствии sentence-transformers — fallback на MockEmbeddingProvider с предупреждением.

## Секция 2. Библиотека синтетических интервью

### 2.1. Структура интервью

Каждое интервью содержит 10 вопросов по трём уровням личности (McAdams, 1995):

**Уровень 1 — Черты (3 вопроса):**
1. Как вы принимаете решения под давлением?
2. Что вас мотивирует в работе больше всего?
3. Как вы обычно реагируете на конфликты с коллегами?

**Уровень 2 — Личные заботы (4 вопроса):**
4. Расскажите о карьерном решении, которым вы гордитесь.
5. Был ли момент, когда вы сомневались в правильности своих действий на работе?
6. Как вы относитесь к ситуациям, когда формальные правила мешают достижению результата?
7. Что для вас значит лояльность коллегам и начальству?

**Уровень 3 — Нарративная идентичность (3 вопроса):**
8. Расскажите историю из детства или юности, которая сформировала ваше отношение к справедливости.
9. Какой эпизод из вашей карьеры определил вас как профессионала?
10. Как бы вы описали себя через 10 лет?

### 2.2. Экспертный синтез

После генерации интервью LLM формирует две экспертные оценки (по модели Park et al. 2024):

- **Оценка психолога:** анализ личностных черт, мотивации, зон уязвимости, вероятных паттернов поведения в стрессовых ситуациях.
- **Оценка экономиста:** анализ отношения к риску, склонности к оппортунизму, реакции на экономические стимулы.

### 2.3. Покрытие и хранение

Матрица генерации: 5 архетипов (idealist, pragmatist, opportunist, initiator, machiavellist) x 4 роли (чиновник, бизнесмен, аудитор, кандидат) x 3 вариации параметров = **60 интервью**.

Хранение: `data/interview_library.jsonl`. Каждая запись содержит:
- `id`: уникальный идентификатор
- `archetype`: архетип коррупционного поведения
- `role`: роль в сценарии
- `hexaco`: параметры HEXACO, использованные при генерации
- `dark_triad`: параметры Dark Triad
- `interview`: словарь вопрос-ответ (10 пар)
- `expert_psychologist`: оценка психолога
- `expert_economist`: оценка экономиста
- `embedding`: вектор эмбеддинга полного текста интервью (384 dim)

### 2.4. Поиск при создании агента

При инициализации агента формируется текстовый запрос из его параметров: HEXACO-профиль, Dark Triad, роль, контекст сценария. По библиотеке выполняется гибридный поиск (BM25 по тексту интервью + косинусное сходство по эмбеддингам). Ближайшее интервью целиком подставляется в промпт агента вместо текущей короткой биографии.

### 2.5. Fallback

Если файл `data/interview_library.jsonl` отсутствует (первый запуск, тесты), используется текущий генератор `biography.py`. Обратная совместимость с существующими сценариями сохраняется.
